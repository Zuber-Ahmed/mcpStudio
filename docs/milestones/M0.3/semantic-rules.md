# Semantic contract and trust boundaries

Contract revision 0.2.0-review synchronizes CA01–CA08. JSON-compatible YAML is intentional. The OpenAPI is a control API, not the generated MCP wire protocol. No server, database or approval enforcement has been implemented by these artifacts.

## Canonical hashing

Algorithm ID `RFC8785+MCPStudio-sets-v1`: normalize UUIDs to lowercase canonical UUID form, SHA256 digests lowercase, reference versions exact strings. Reject duplicate selected IDs/scope names/check names. Sort set-valued collections by stable IDs before RFC 8785 JCS serialization. Ordered arrays (such as command arguments inside plugin config) retain order. Do not indiscriminately sort all arrays. Nonfinite numbers, duplicate JSON object keys, malformed Unicode and out-of-safe-integer values are rejected. No confidence scores enter executable payloads. User configuration JSON schemas may contain finite floats, so a real RFC 8785 implementation is required: Python sort_keys is not sufficient.

The plan digest is SHA256 of UTF-8 canonical plan bytes. Artifact-set digest is SHA256 over JCS of an array of `{path,sha256,size_bytes}` ordered by normalized relative path; reject case-colliding paths for Windows portability. Raw secret values never enter either payload. SHA vectors for a restricted ASCII/integer subset are provided for independent cross-language checks; full RFC Unicode/numeric vectors still gate interoperability until the canonicalizer dependency can be retrieved.

## Bootstrap/session design

Only loopback API exposure is permitted. A host-side setup operation generates >=256-bit random one-time bootstrap secret in an OS-protected user store, binds a short-lived one-use exchange to exact local origin and a fresh browser nonce, and never prints it into project logs, URLs or generated files. Exchange is a planned host launcher mechanism, not a public permanent API route in this contract. No credential is hardcoded.

After exchange, API stores only hashed session credential and sets HttpOnly, SameSite=Strict, host-only session cookie (Secure required for TLS; explicitly documented loopback HTTP development exception). Browser mutation also needs a session-bound CSRF token and exact Origin allowlist. CORS is denied by default; no wildcard credential access. Cross-site/unknown/null origins denied. Local bearer credentials remain for host tools; cookie and bearer subjects must not conflict. Sessions expire after 30 minutes idle/8 hours absolute; logout revokes session; bootstrap nonce expires in 60 seconds and cannot replay. Rotation revokes previous bootstrap secret. State is scoped to the one local operator/tenant; no signup/admin product.

The separate specs/bootstrap.openapi.yaml defines exchangeBootstrapCode, getLocalSession and logoutLocalSession. Current 24 resource operations exclude these 3 bootstrap operations. Refresh of idle expiry is server-controlled on authorized activity, never beyond absolute expiry; getLocalSession returns updated CSRF/expiry information with no-store. Implementation and session security tests remain a foundation hold. Persisted INFERENCE_CONSENT/IDEMPOTENCY/OUTBOX are operational data; session store implementation and OS credential integration require Windows verification.

SEM-BOOTSTRAP: exchange is unauthenticated only in the HTTP-scheme sense: a one-time 256-bit code, independent browser nonce, exact allowed loopback Origin and host launcher binding are all required. The launcher binds both code and nonce to the intended browser and expiry through host IPC, not URL query/fragment or console. Single-use compare-and-consume is atomic and failed/replayed exchange is rejected/rate-limited. Never cache response/secret/body in logs. Successful response sets host-only HttpOnly/SameSite Strict cookie; GET session returns only operator/tenant/CSRF/expiry, never the session credential. Logout verifies Origin+CSRF, revokes server-side session and clears cookie. A bearer token cannot be used to obtain another actor's cookie session. The host tool obtains/revokes local bearer credentials through its OS store, not an HTTP signup route. Explicit loopback HTTP development cookie exception requires exact-origin protection; HTTPS profile uses Secure cookie.

Workflow summary uses only the latest effective source/plan/generation lineage; historical failed runs do not permanently block a later valid lineage. If multiple phases in that lineage are active, display validating before generating before analyzing; preserve detailed statuses and IDs. This deterministic projection never changes gate authority.

## Worker boundary / readiness proof

Acquisition creates immutable snapshot outside the original repo; scan worker receives read-only mount with no shell/project scripts. Validation gets read-only snapshot, separate writable output/temp, no production environment, deny network, explicit CPU/memory/time and process cleanup. Container existence alone is not a sandbox guarantee. A prerequisite fixture must try path traversal/symlink escape, source write, egress and timeout, with negative evidence and cleanup. Docker/WSL missing or inaccessible means blocked, never host-native fallback.

Data lifecycle initially local until operator cleanup, with explicit path/retention disclosure. Never claim zero persistence. Delete temporary worker directories safely within verified roots; preserve approval/audit evidence per documented cleanup choice. Artifact previews offset/limit refer to UTF-8 byte windows; API must avoid splitting invalid UTF-8 and return actual next_offset. Logs use cursor/limit, no unbounded downloads. Graph limit returns structured 422 `graph_limit_exceeded` rather than partial unmarked graph. Policy checks, identity propagation and origin handling need live tests later.

## Persistence nullability and mapping

ERD is logical; diagram one-to-many edges identify dependencies when the child reference exists. In particular analysis.consent_id, previous_run_id and completion/revocation fields are conditional/nullable; finalized digests exist only after completion. `PROJECT` workflow/latest-run fields are projections from runs/plans, not duplicated authorities. JSON fields have versioned resource schemas from OpenAPI and canonical payload; unknown plugin config requires installed plugin schema check. Stable Finding IDs in public reports map to FINDING.stable_key, not database UUIDs. Physical DDL and enforcement tests are pending, not represented as passed by dictionary consistency.
